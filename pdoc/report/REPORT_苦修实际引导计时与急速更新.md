# 苦修实际引导计时与急速更新

负责人、开发及测试：Solazhu

日期：2026-11-17

## 目标与范围

基于 `63179d0b3a2894174bd451045303a1da70736722`，在 `codex/spell-efficiency-penance-timing` 独立分支修复。用户确认采用实际施法校准：首次施放及急速变化后再次施放时读取完整引导时间，尚未得到新计时前使用面板。发布版本为 `0.1.7-test`，已获授权提交、推送、合并至 `main` 并安装到无限服游戏目录。

保留完整三发、同一行红色伤害与蓝色治疗、已有 GCD 规则与手动时间权重。其他引导法术沿用原来的时长来源；精神鞭挞等引导攻击技能记为后续适配范围，本次不扩大实际计时校准范围。

## 实现

- 已有描述解析额外标识苦修类型，避免按名字猜测或将其他引导技能纳入校准。
- 玩家引导开始时核对已学会的法术 ID 与当前引导 ID，读取 `UnitChannelInfo("player")` 的开始、结束毫秒值。完整秒数为 `(endTimeMs - startTimeMs) / 1000`，不再乘除急速，不用剩余时间。
- 每个苦修等级仅在本次会话保留最近一条时长和对应急速，后续施法覆盖。急速改变或急速事件中读不到可信值时清除旧记录；悬停也核对急速，关闭效率提示清空记录。未知急速下仍可采用新采集的实际时长，但后续急速事件会使该记录失效。
- 急速变化后重建当前有效原生技能提示，重新调用原始 getter 获取最新标题、描述，再更新效率行。校准成功后也立即更新当前可见提示；隐藏或其他类型的提示不会被唤起。
- 计时不可用、异常、法术不匹配或读取失败时回退标题时长、描述时长，下一次施法可以恢复。不会用受击更新、提前中断或停止事件改写完整施法的初始计时。

运行时仅增加按已校准苦修等级存储的小表和一个玩家引导开始事件。无轮询、定时器、历史序列或新增保存字段；不改动原生点击、施法和受保护操作。

## 验证

先运行原有测试，278 项通过。加入实际计时用例后，旧实现复现失败：模拟接口返回完整 1.6 秒，但效率仍显示按 2 秒得到的治疗 1.65、伤害 0.60。

修复后 Lua 5.1 全部 290 项通过，其中法术效率 126 项、拍卖助手基线 164 项。新增 12 项覆盖实际时间差、避免二次急速、无悬停校准、不同等级、急速失效与恢复、隐藏期间急速往返、原生数据重读、非法与不可读数据、中断保护、开关及权重。旧的关闭功能测试改为检查本次重建次数增量，避免将前面急速事件的正常重建算入关闭操作。

截图数值为完整治疗 432、伤害 156、耗蓝 150；权重 0.8 时，合成的完整 1.6 秒计时对应治疗 1.98、伤害 0.71。测试故意将急速设为 50%，以验证算法使用接口返回的 1.6 秒，绝不再缩短一次；这不是对无限服实际急速比例的断言。
