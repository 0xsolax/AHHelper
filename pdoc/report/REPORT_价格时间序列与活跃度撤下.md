## 交付范围

按确认范围移除「增 / 减 / 波动」列、活跃度运算与会话状态，保留关注成品自动刷新、原有队列节流和取消请求回收。原列改为「售价采样时间」，悬停显示完整日期时间和对应最低单价；原生页面的较新价格缓存不会给旧的监控报价贴上新时间。

每次插件完成关注成品查询，保存产品编号、服务器绝对时间戳和最低单价，价格不变也追加。完整无一口价结果用 `false` 标识；失败、不完整、暂停和未采集期间不生成价格点。每角色在载入和新增成品样本时按最近 48 小时、最多 30000 条清理，以先到者为准；样本序号在清理和重载后不重用。删除关注产品停止新增，其历史仍按保留规则处理。

记录位于 `AuctionPilotDB.profiles[角色键].priceHistory`，格式和外部读取约定见插件 README 的「自动刷新与价格时间序列」。关闭拍卖行不清空序列，重载后恢复存档，不自动恢复查询开关或把历史数据当作当前利润报价。旧配置、商店价和最后价格缓存继续沿用；未知或损坏的序列格式提示并原样保留。

原生搜索列表与商品明细都会记录普通商品的最后价格和时间，包括未关注物品。列表只读取本次搜索或翻页已返回的行，不新增查询或补页；装备、宠物、属性变体排除。延迟到达的物品资料保留原价格时间，旧结果不覆盖新价格，同秒列表参考不覆盖完整明细报价。背包提示区分「上次搜索参考价」和「上次最低单价」；这些被动记录不进入连续历史序列或利润计算。正在回收的取消请求不刷新明细缓存。本版未包含外部读取、长期归档和趋势页面程序。

关闭再打开拍卖行，保留本次会话已有的完整报价并标为历史测算；刷新失败沿用旧值、原时间并显示失败原因，下一次完整结果才替换。从未拿到完整报价时保持未知；成功返回空市场或不足数量时不继续展示旧利润。保存配方后按当前用量和价格来源重算，删除最后一个引用后释放对应会话报价。

会话利润不另存结果或追加记录，仅复用内存中的最新报价；`/reload`、退出或换角色后可清空。最低价按钮、自动填价及竞争比较继续要求有效的新报价，失败或重开后不使用历史报价；用户手工填写的价格保留。

## 交付授权与实机验收

首轮交付停留在上述本地分支。2026-11-12 用户追加授权提交、推送、合并到 `main`，然后安装到现有游戏插件目录。本次按此范围交付：安装前备份原插件，仅覆盖本插件的已验证文件，保留游戏保存数据；已有插件覆盖后可在游戏内 `/reload`。源码合并、文件安装与实机验收分别核对。

实机应核对：自动刷新只查关注成品；同价刷新仍有新时间；暂停和失败不产生价格点；悬停显示对应价格的完整日期时间；重载后的序列、样本序号与配置保留。搜索一个未关注材料后直接查看背包提示，核对价格、来源和时间，并检查翻页与物品资料延迟时的更新。关闭再打开拍卖行应保留历史利润，刷新成功更新；刷新失败保留旧值并标记，完整空市场显示未知；重载后不从价格存档恢复利润。真实服务端事件顺序、字体和客户端流畅度尚未实测。

只有 `/reload` 或正常结束会话后，外部程序才能读取已落盘的最新记录。超过缓存限制且未导出的样本无法补回。
