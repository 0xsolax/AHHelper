# 法术效率时间权重 0.8

日期：2026-11-16

负责人、开发、验证：Solazhu

## 结果与范围

从已发布提交 `53f4f48c224b595e5e896f044b3f220c5cafc8d5` 建立独立分支 `codex/spell-efficiency-time-weight`。按照确认的口径，将效率改为：

```text
加权效率 = 效果 / 耗蓝 / (有效占用秒数 ^ 0.8)
```

只调整原有 `Logic.Score` 的时间分母。有效占用仍取当前读条或完整引导时长与当前 GCD 的较大值；急速、数据暂缺时的默认 GCD、HoT/DoT 完整效果、关联治疗、单行标题和红蓝显示继续沿用现有行为。同步更新插件简介与 README，明确这是比较用的加权分数，而非严格的每蓝每秒效果。没有新增配置、运行文件、轮询、缓存或保存数据。

交付版本为 `0.1.3-test`。用户已授权提交、推送、合并到 `main`，并备份后安装到无限服游戏的 `SpellEfficiency` 目录；保持游戏运行，由用户 `/reload` 验证。

## 验证

先调整时间计算用例并新增权重、比较结果用例，在旧公式上复现 4 项预期失败。随后修改公式并更新现有提示框数值预期，保留原有输入和显示、异常、生命周期检查。

使用项目本地 Lupa / Lua 5.1 执行 `tests/run_tests.py`，退出码 0，共 247 项通过：法术效率 83 项，基线拍卖插件 164 项。

- 时间翻倍，分数变为约 57.4%；耗蓝翻倍仍减半，效果翻倍仍翻倍。
- 合成样本中，效果 600、耗蓝 100、占用 1.5 秒的分数由 4.00 变为 4.34；效果 1100、耗蓝 100、占用 3 秒的分数由 3.67 变为 4.57，证明公式能改变比较结果，而非统一放大分数。
- 验证瞬发、读条、引导及 1 秒基准；原有急速更新、缺失后恢复、蓝色治疗、红色伤害、护盾及无重复行检查通过。

上述为离线合成测试，本轮未进行游戏内验收。
