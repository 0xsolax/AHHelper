# 查询队列超时恢复与喝药报错排查

负责人、修改人、操作人：Solazhu

日期：2026-11-13

修复分支：`codex/fix-refresh-recovery`。基线为 `main` 的 `713cc79ed171c3f499d8f8f1d45126596b86c8dd`（0.8.0-test），交付版本为 0.8.1-test。用户于 2026-11-13 授权提交、推送、合并到 main，并备份后覆盖游戏插件；安装后在游戏内 `/reload` 验收。实际交付状态和校验结果记入本地安装回执。

## 问题与证据

用户反馈点击“全部刷新”后只完成前几个产品，超过一分钟仍显示查询中，未保留当时底部状态和客户端错误记录。因此不能确定此次实机卡住一定由限流引起，也不能仅据此归因为性能或扫描强度。

源码中存在两个可复现缺口：拍卖行不允许发送时，队列在建立当前请求之前直接返回，没有等待期限，刷新按钮因剩余队列永久禁用；已发送请求虽有 25 秒超时，但失败后没有重试。新测试在旧代码上复现第一处问题：达到限流等待期限后预期队列为空，实际仍有 3 项。

接口依据：[拍卖行 API 定义](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/AuctionHouseDocumentation.lua)。`IsThrottledMessageSystemReady` 表示当前能否发送受节流限制的消息；`SendSearchQuery` 无成功返回值，不能把 Lua 调用未抛异常当成已经收到完整行情。搜索结果事件只带物品标识，没有本次请求编号。

## 最小修复范围

- `Market.lua`：复用串行队列和每 0.25 秒检查的计时器，发送间隔仍至少 1.2 秒。一次查询包括补页，25 秒无完整结果则失败。临时发送错误、读取错误、不完整明细、补页错误、服务器报错或超时，排到队尾重试一次；不支持的装备、宠物直接计为失败。
- 失败后其余物品继续查询。同一物品在明确失败后至少等 3 秒，超时后等 25 秒，再允许重试；冷却中的物品不会挡住其他物品。后一个窗口用于隔离未结束请求的迟到响应。重试再次失败即结束该项，不无限重试。
- 连续 30 秒不可发送时，清空本轮执行队列、关闭自动刷新并恢复按钮；保留本轮计数和限流原因，用户可重新点击刷新。尚未完成的项目显示为待查，不伪造为成功、空市场或已逐项查询失败。
- `UI.lua`：显示完成、失败、待查数量，以及当前查询、补页、限流等待、重试次数和等待倒计时。完成表示成功取得完整结果，失败表示最终失败；一件物品重试不重复累计总量。过长状态按现有方式限制在一行。
- `History.lua`：失败隔离期的迟到事件也不能绕过队列，写入被动记录的最近价。原有取消请求隔离继续保留；切页、编辑、关闭拍卖行会取消未执行的重试。

失败保留上一次完整报价、原采样时间和历史利润；无完整旧报价仍显示缺价。只有成功取得完整结果后才更新报价和价格序列；完整空市场仍正确覆盖旧值。查询范围、共享材料去重、自动刷新只查关注成品以及手动交易边界保持原有行为。

本轮只新增一份当前批次计数/尝试次数和短期响应隔离时间，数量随本轮物品数增长；隔离到期即清理，不积累历史挂单，不增加 SavedVariables 数据，也不创建新的计时器或后台扫描。

新增回归包括：

- 首项无响应时后续两项成功，之后首项只重试一次；整批都无响应仍会结束，每项总计两次尝试。
- 临时发送失败、读取与补页 API 抛错、同步服务器报错后发送函数再次抛错，均不导致重复重试或卡住后续项目。

## 喝药报错调查

用户确认入口是背包右键药水，未提供被拦截函数或战斗状态，并选择暂不复现。现有游戏日志目录未发现可用的 taint/Lua 错误记录；本轮未修改此部分代码。

`Widgets.InstallItemLinks` 确实直接替换了原生 `ChatFrameUtil.InsertLink`（兼容回退为 `ChatEdit_InsertLink`），用途是接收编辑器中 Shift 点击的物品链接。这是需要进一步排查的安全执行路径变更，但现有证据不足以认定它导致普通右键喝药失败。

在核对的原生界面源码中，[普通背包点击](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ContainerFrame.lua#L1683-L1697)与修饰键点击分别分派；使用物品会进入 [`C_Container.UseContainerItem`](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ContainerFrame.lua#L1605-L1615)，[修饰键分支](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_ItemButton/Mainline/ItemButtonTemplate.lua#L372-L403)才会尝试插入物品链接。不能用“仅安装一个插件”替代污染传播路径和被拦截函数的证据。

后续复现时可执行 `/console taintLog 1` 后 `/reload`，按平时操作复现，再读取游戏 `Logs` 下实际生成的记录，结束后执行 `/console taintLog 0`。本轮未要求退出游戏、未更改日志设置，也未新增常驻诊断代码。

## 实机边界

离线回归证明指定失败模型下队列能够结束、重试有上限且历史数据边界保持；尚未在游戏中验证网络延迟、实际限流或喝药报错。接口没有请求编号，有限隔离窗口不能证明任意长延迟的同物品旧响应都可识别。下一步实机应重点检查“全部刷新”能否扫到最后、失败项是否明确结束，以及限流停止后能否再次手动刷新。
