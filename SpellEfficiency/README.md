# 法术效率 SpellEfficiency 0.1.7-test

负责人、开发及测试：Solazhu

独立插件。有法力池的角色可以开启五秒回蓝瓶。牧师与德鲁伊还可在法术书或动作条的原生技能提示框底部查看一行效率：

> 效率：治疗 2.00　伤害 1.00

治疗文字和数值为蓝色，伤害文字和数值为红色。混合技能同时显示两项；单一效果只显示对应项。护盾以蓝色“吸收”单独标明。

数据来自当前客户端，无外部数据服务。面向无限服 `_forever_`，适配 `Interface 16001`，本机客户端文件版本为 `1.60.1.70938`；描述解析支持简体中文和英文。离线测试已完成，本次修复的游戏内效果尚待验证。

## 使用

悬停已学会的牧师或德鲁伊职业法术即可查看效率。比较低等级与高等级时，可在原生法术书中打开“显示所有等级”，或将不同等级放到动作条后分别悬停。插件按提示框实际显示的法术 ID 取数，不使用同名法术的最高等级替代。

插件目录是 `SpellEfficiency`，无需依赖 `AuctionPilot`，两者可以分别启用。将本目录放在游戏的 `Interface/AddOns/` 下，并在插件列表确认“法术效率”已启用。

有法力池的角色可左键点击小地图旁的“效率”按钮打开设置，按住左键拖动可调整按钮位置。牧师与德鲁伊右键切换效率提示，只有回蓝监控的角色右键切换回蓝瓶。牧师与德鲁伊可勾选“显示法术效率”，手填 `0～1` 的时间权重，点击“应用”或按回车生效。非法输入会保留原设置。点击“恢复默认 0.8”会开启效率提示并恢复时间权重。关闭窗口会放弃尚未应用的效率设置。

权重越小，比较时越偏重每蓝收益：`0` 只看效果／耗蓝，`1` 完整计入时间，默认 `0.8` 保持原有算法。设置按角色保存，`/reload` 或正常退出后保留，无需每次重填。

## 五秒回蓝瓶

勾选“显示五秒回蓝瓶”立即生效，默认关闭。竖瓶默认位于屏幕中央下方，尺寸为 48 × 96 界面单位。打开“效率”设置时，可按住蓝瓶拖到需要的位置，关闭设置后锁定，位置按角色保存。空蓝及德鲁伊猫熊形态仍按角色的法力上限判断是否可用。

每次开启时默认显示满瓶，已开启的角色 `/reload` 后也从满瓶开始。确认耗蓝后，瓶内清空，蓝色液体在五秒内自底向上注满。每轮注满时，瓶口的三股蓝光旋起，化作蓝雾向上散去，约两秒播放一次。满瓶且可见时，蓝白光和星芒约两秒明暗一轮。再次耗蓝、隐藏或关闭时立即停止蓝雾和闪动。恢复显示时，满瓶继续闪动。液面表示时间进度。五秒期内精神回蓝受到限制，其他回蓝来源仍可能生效。

倒计时用自己的施法事件和可读法力费用估算。普通读条在成功时开始计时，引导按开始扣费处理，同一次引导的成功事件只计一次。免蓝、其他资源消耗、未完成的读条和费用不可读的事件不会重置。仅有周期费用时略过，免蓝优先参考同一施法发出或开始时读取的费用。实际扣蓝时点和费用是否可读还需在无限服实测。

## 数值口径

```text
加权效率 = 单个目标的面板效果 / 本次耗蓝 / (有效占用秒数 ^ 时间权重)
普通施法的有效占用 = max(当前读条秒数, 当前公共冷却秒数)
引导施法的有效占用 = max(完整引导秒数, 当前公共冷却秒数)
时间权重为 0 时，直接使用面板效果 / 本次耗蓝，不要求时间数据就绪
```

- 区间伤害或治疗取平均值；同一次施法的直接及持续效果属于同一类别时相加。
- 持续伤害、持续治疗取完整持续期的总量，不表示这些效果会立即生效。明确写明每跳效果、跳频及持续时间时换算总量；跳数不明确时不给数值。
- 苦修支持中英文“立即生效，随后按间隔重复”的完整描述：总次数 = 1 + 后续持续时间 / 间隔。面板每发治疗、伤害分别乘总次数；完整引导效率仍使用整次耗蓝和当前时间权重，同一行保留蓝色治疗、红色伤害。已识别的苦修描述缺少首发、时长或间隔，或包含尚未支持的额外效果时，显示“无法估算”。
- 群体法术按单个目标计算，不假定命中或治疗人数。混合伤害与治疗的法术分别计算两项效率，并在同一行保留；护盾使用吸收量。不同类别不相加。
- 伤害转治疗支持“恢复等量生命”和明确的伤害百分比：治疗总量 = 完整伤害总量 × 回血比例。持续伤害先合计再换算治疗，不再重复乘跳数。缺少伤害基数、比例不明确、重复关联或同时出现可能重复的固定治疗描述时显示“无法估算”。
- 耗蓝读取对应法术 ID 的当前资源消耗，区分常规费用和满足光环条件的替代费用。接口缺失不解释成零耗蓝。
- 德鲁伊仍按每蓝收益计算：直接治疗与完整持续治疗可合计；直接伤害与完整持续伤害可合计，群体或引导效果按单个目标的完整总量。英文愈合类描述省略第二个治疗动词时，也保留明确的后续治疗量。已确认使用怒气、能量、连击点等资源的技能显示“不适用”，包括同时要求其他资源的技能；不会把它们当成零耗蓝。形态切换后，每次悬停重读当前生效的费用，不根据角色当前显示的资源条猜测法术消耗。
- 读条时间读取客户端；普通引导优先采用标题明确标示的时长，否则采用描述中可确认的完整时长。苦修优先使用当前急速下、同一等级的实际施法计时；还没有有效计时时也按标题、描述的顺序回退。
- 苦修首次施放、或急速改变后再次施放时自动校准：在引导开始事件读取客户端的开始与结束时间，使用两者的完整秒数差。这个值已包含客户端对该次引导的修正，不再除以急速，也不使用剩余时间。受击更新和提前中断不改写完整引导计时，防止将三发效果除以残缺施法时间。每个等级单独记录，急速改变、无法确认急速状态、关闭效率提示或 `/reload` 后重新校准；校准前仍显示面板时长对应的效率，不猜测无限服引导是否受急速影响。
- 苦修描述中的 2 秒、每 1 秒重复，表示立即一发加后续两发；次数仍来自描述，实际计时只替换时间分母。实际计时接口无法读取、时间异常或法术 ID 不匹配时回退面板，后续施法可重新校准。
- 公共冷却以 `GetSpellBaseCooldown` 的基础值和当前 `UnitSpellHaste("player")` 修正：基础秒数 ÷（1 + 法术急速百分比 ÷ 100）。无限服常规法术按 1.0～1.5 秒限制；本身更短的基础 GCD 不会被抬高，零 GCD 保持零。读条时间已由客户端提供，不再额外除一次急速；法术自身冷却和剩余冷却不参与分母。版本口径见[无限服问题记录 #389](https://github.com/ClassicWoWCommunity/forever-bugs/issues/389#issuecomment-6308929421)。
- 急速尚未就绪时，先按基础 GCD 显示效率；基础 GCD 也缺失时，牧师与德鲁伊的耗蓝法术使用默认的 1.5 秒。急速可读取后恢复修正；收到玩家急速更新事件时，清除不再适用的苦修计时，并让仍打开的技能提示框重新读取原生数据后更新效率行。重新悬停也会核对当前急速；不会仅因急速或基础 GCD 暂缺而显示“时间未知”。

时间先换算为秒、确定读条或引导与 GCD 的较大值，再取所选权重的次方；不把时间直接乘权重。效果和耗蓝保持原权重：耗蓝翻倍时分数减半；默认 `0.8` 下，有效占用时间翻倍时分数约为原来的 57.4%。提示框仍只显示一行“效率”，治疗蓝色、伤害红色。

这是可调整时间权重的面板分数，只有权重为 `1` 时代表每蓝每秒效果，适合在相同条件和权重下比较同一法术的等级。插件不额外套用法强或天赋系数，也不估算暴击、抗性、过量治疗、实际命中人数、中断或持续效果覆盖率。面板未反映的加成不会凭空补入。

## 无法给出数值时

仍只使用同一行显示状态：

| 情况 | 显示 |
| --- | --- |
| 已识别的非数值效果，如一般增益、复活、被动；已确认使用非蓝资源的技能 | 不适用 |
| 明确零耗蓝 | 当前免耗蓝 |
| 文本尚未加载 | 数据未就绪 |
| 费用缺失；权重大于 0 且读条或引导时间缺失、有效占用时间为零 | 耗蓝未知 / 时间未知 |
| 无法确定基数的百分比、触发次数不定、未支持的资源转化、无法确认的文本格式 | 无法估算 |
| 客户端读取暂时失败或数据不可访问 | 暂不可用 |

各等级共用解析规则，未硬编码伤害、耗蓝或等级数量。分支已经验证等级取数路径，但没有实机逐一核验牧师与德鲁伊所有法术的文本；发现无法确认的数值或关联关系时显示状态，不冒用其他等级的数据。荆棘反伤、依赖目标已有持续治疗的效果、受攻击触发、点击光井、按消耗资源折算伤害等条件效果，本版没有建立战斗模型；仅在当前面板明确给出可计算的总量时使用该总量。

## 性能与保存

在原生提示框生成、重建、玩家急速更新或设置应用时计算当前法术；苦修引导开始时读取一次完整时长并更新当前可见的效率行，不需要一直悬停才能校准。急速事件只更新当前可见且已有本插件内容的技能提示框；关闭、清空或切换到物品提示框时不查询旧技能。关闭效率提示后停止其数值查询，并移除当前提示框中的效率行。重复回调更新同一行；错误只影响当前次更新，下一次事件或原生更新会重读。

`SavedVariablesPerCharacter: SpellEfficiencyDB` 保存当前角色的效率开关、时间权重、小地图位置角度、回蓝监控开关和蓝瓶位置。苦修计时按已校准等级保留最近一条时长与对应急速。回蓝截止时间和施法费用保留到关闭监控或重载。注入时按 0.1 秒更新液面。蓝雾按经过时间从预渲染贴图中取帧，每秒最多换 24 帧，仅在播放期间更新。满瓶闪动由客户端调整原有光晕的透明度，Lua 只在状态切换时开始或停止闪动。关闭回蓝瓶会解除施法监听。拖动小地图按钮时临时逐帧定位，松开或隐藏后停止。设置窗口首次打开时创建。
