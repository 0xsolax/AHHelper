# 法术效率 SpellEfficiency 0.1.0-test

负责人、开发及测试：Solazhu

独立插件。在牧师法术书或动作条的原生技能提示框底部只增加一行，例如：

> 每蓝每秒效果：治疗 2.00　伤害 1.00

治疗文字和数值为蓝色，伤害文字和数值为红色。混合技能同时显示两项；单一效果只显示对应项。护盾以蓝色“吸收”单独标明。

数据来自当前客户端，无外部数据服务。适配 `Interface 16001`，本机客户端文件版本为 `1.60.1.70938`；描述解析支持简体中文和英文。离线测试已完成，游戏内悬停效果尚待验证。

## 使用

悬停已学会的牧师职业法术即可查看。比较低等级与高等级时，可在原生法术书中打开“显示所有等级”，或将不同等级放到动作条后分别悬停。插件按提示框实际显示的法术 ID 取数，不使用同名法术的最高等级替代。

插件目录是 `SpellEfficiency`，无需依赖 `AuctionPilot`，两者可以分别启用。将本目录放在游戏的 `Interface/AddOns/` 下，并在插件列表确认“法术效率”已启用。

## 数值口径

```text
每蓝每秒效果 = 单个目标的面板效果 / 本次耗蓝 / 有效占用秒数
普通施法的有效占用 = max(当前读条秒数, 基础公共冷却秒数)
引导施法的有效占用 = max(完整引导秒数, 基础公共冷却秒数)
```

- 区间伤害或治疗取平均值；同一次施法的直接及持续效果属于同一类别时相加。
- 持续伤害、持续治疗取完整持续期的总量，不表示这些效果会立即生效。明确写明每跳效果、跳频及持续时间时换算总量；跳数不明确时不给数值。
- 群体法术按单个目标计算，不假定命中或治疗人数。混合伤害与治疗的法术分别计算两项效率，并在同一行保留；护盾使用吸收量。不同类别不相加。
- 耗蓝读取对应法术 ID 的当前资源消耗，区分常规费用和满足光环条件的替代费用。接口缺失不解释成零耗蓝。
- 读条时间读取客户端；引导时间优先采用标题明确标示的时长，否则采用描述中可确认的完整时长。
- 公共冷却取 `GetSpellBaseCooldown` 的基础值，首版不另外修正其急速变化；该接口不存在时使用 1.5 秒参考值。该接口返回零时保留零，无法形成有效时间则显示“时间未知”。法术自身冷却和剩余冷却不参与分母。

这是面板估算分数，适合在相同条件下比较同一法术的等级。插件不额外套用法强或天赋系数，也不估算暴击、抗性、过量治疗、实际命中人数、中断或持续效果覆盖率。面板未反映的加成不会凭空补入。

## 无法给出数值时

仍只使用同一行显示状态：

| 情况 | 显示 |
| --- | --- |
| 已识别的非数值效果，如一般增益、复活、被动 | 不适用 |
| 明确零耗蓝 | 当前免耗蓝 |
| 文本尚未加载 | 数据未就绪 |
| 费用或时间缺失 | 耗蓝未知 / 时间未知 |
| 百分比、触发次数不定、资源转化、无法确认的文本格式 | 无法估算 |
| 客户端读取暂时失败或数据不可访问 | 暂不可用 |

各等级共用解析规则，未硬编码伤害、耗蓝或等级数量。分支已经验证等级取数路径，但没有实机逐一核验牧师所有法术的文本；无法识别的格式会显示状态，不会冒用其他等级或只计算一半效果。受攻击触发、点击光井、按消耗资源折算伤害等条件效果，本版没有建立战斗模型。

## 性能与保存

只在原生提示框生成或重建时计算当前法术，没有逐帧轮询、定时扫描或整本法术书的循环查询。重复回调更新同一行；错误只影响当前次悬停，下一次原生更新会重读。

不建立战斗记录或历史缓存；不声明 SavedVariables，持久化数据量为零。插件不创建独立面板或动作条文字，不替换原生施法、动作条或背包的点击处理函数。
