# 法术效率 SpellEfficiency 0.1.3-test

负责人、开发及测试：Solazhu

独立插件。在牧师法术书或动作条的原生技能提示框底部只增加一行，例如：

> 效率：治疗 2.00　伤害 1.00

治疗文字和数值为蓝色，伤害文字和数值为红色。混合技能同时显示两项；单一效果只显示对应项。护盾以蓝色“吸收”单独标明。

数据来自当前客户端，无外部数据服务。面向无限服 `_forever_`，适配 `Interface 16001`，本机客户端文件版本为 `1.60.1.70938`；描述解析支持简体中文和英文。离线测试已完成，本次修复的游戏内效果尚待验证。

## 使用

悬停已学会的牧师职业法术即可查看。比较低等级与高等级时，可在原生法术书中打开“显示所有等级”，或将不同等级放到动作条后分别悬停。插件按提示框实际显示的法术 ID 取数，不使用同名法术的最高等级替代。

插件目录是 `SpellEfficiency`，无需依赖 `AuctionPilot`，两者可以分别启用。将本目录放在游戏的 `Interface/AddOns/` 下，并在插件列表确认“法术效率”已启用。

## 数值口径

```text
加权效率 = 单个目标的面板效果 / 本次耗蓝 / (有效占用秒数 ^ 0.8)
普通施法的有效占用 = max(当前读条秒数, 当前公共冷却秒数)
引导施法的有效占用 = max(完整引导秒数, 当前公共冷却秒数)
```

- 区间伤害或治疗取平均值；同一次施法的直接及持续效果属于同一类别时相加。
- 持续伤害、持续治疗取完整持续期的总量，不表示这些效果会立即生效。明确写明每跳效果、跳频及持续时间时换算总量；跳数不明确时不给数值。
- 群体法术按单个目标计算，不假定命中或治疗人数。混合伤害与治疗的法术分别计算两项效率，并在同一行保留；护盾使用吸收量。不同类别不相加。
- 伤害转治疗支持“恢复等量生命”和明确的伤害百分比：治疗总量 = 完整伤害总量 × 回血比例。持续伤害先合计再换算治疗，不再重复乘跳数。缺少伤害基数、比例不明确、重复关联或同时出现可能重复的固定治疗描述时显示“无法估算”。
- 耗蓝读取对应法术 ID 的当前资源消耗，区分常规费用和满足光环条件的替代费用。接口缺失不解释成零耗蓝。
- 读条时间读取客户端；引导时间优先采用标题明确标示的时长，否则采用描述中可确认的完整时长。
- 公共冷却以 `GetSpellBaseCooldown` 的基础值和当前 `UnitSpellHaste("player")` 修正：基础秒数 ÷（1 + 法术急速百分比 ÷ 100）。无限服常规法术按 1.0～1.5 秒限制；本身更短的基础 GCD 不会被抬高，零 GCD 保持零。读条时间已由客户端提供，不再额外除一次急速；法术自身冷却和剩余冷却不参与分母。版本口径见[无限服问题记录 #389](https://github.com/ClassicWoWCommunity/forever-bugs/issues/389#issuecomment-6308929421)。
- 急速尚未就绪时，先按基础 GCD 显示效率；基础 GCD 也缺失时，使用牧师默认的 1.5 秒。急速可读取后恢复修正；收到玩家急速更新事件时，仍打开的技能提示框会直接更新同一行，重新悬停或原生重建时也会重读。不会仅因急速或基础 GCD 暂缺而显示“时间未知”。

时间先换算为秒、确定读条或引导与 GCD 的较大值，再取 0.8 次方；不把时间直接乘 0.8。效果和耗蓝保持原权重：耗蓝翻倍时分数减半，有效占用时间翻倍时分数约为原来的 57.4%。提示框仍只显示一行“效率”，治疗蓝色、伤害红色。

这是偏重每蓝收益的面板加权分数，不再代表严格的每蓝每秒效果，适合在相同条件下比较同一法术的等级。插件不额外套用法强或天赋系数，也不估算暴击、抗性、过量治疗、实际命中人数、中断或持续效果覆盖率。面板未反映的加成不会凭空补入。

## 无法给出数值时

仍只使用同一行显示状态：

| 情况 | 显示 |
| --- | --- |
| 已识别的非数值效果，如一般增益、复活、被动 | 不适用 |
| 明确零耗蓝 | 当前免耗蓝 |
| 文本尚未加载 | 数据未就绪 |
| 费用缺失；读条或引导时间缺失、有效占用时间为零 | 耗蓝未知 / 时间未知 |
| 无法确定基数的百分比、触发次数不定、未支持的资源转化、无法确认的文本格式 | 无法估算 |
| 客户端读取暂时失败或数据不可访问 | 暂不可用 |

各等级共用解析规则，未硬编码伤害、耗蓝或等级数量。分支已经验证等级取数路径，但没有实机逐一核验牧师所有法术的文本；发现无法确认的数值或关联关系时显示状态，不冒用其他等级的数据。受攻击触发、点击光井、按消耗资源折算伤害等条件效果，本版没有建立战斗模型。

## 性能与保存

在原生提示框生成、重建，或玩家急速更新事件到达时计算当前法术。急速事件只更新当前可见且已有本插件内容的技能提示框；关闭、清空或切换到物品提示框时不查询旧技能。没有逐帧轮询、定时扫描或整本法术书的循环查询。重复回调更新同一行；错误只影响当前次更新，下一次事件或原生更新会重读。

不建立战斗记录或历史缓存；不声明 SavedVariables，持久化数据量为零。插件不创建独立面板或动作条文字，不替换原生施法、动作条或背包的点击处理函数。
